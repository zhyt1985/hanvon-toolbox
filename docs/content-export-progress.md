# 内容导出开发进展

更新日期：2026-11-19\
状态：基础导出、独立无线只读来源及 0.7.1 设备固定副本已完成本轮 N10 Plus 隔离样例验收。尚未达到设计文档定义的完整首版。

## 第三阶段 设备端固定副本（本轮已验收）

伴侣 0.7.1 与新 Mac 构建已实现所选内容的异步固定副本。当前已构建并签名，72 项 Swift 测试、12 个套件通过；独立 Java 采集测试通过 11 项检查。0.7.1 APK 已通过 USB 放入 Download 并读回校验；用户已覆盖安装、添加并批准本轮合成来源，本轮真机验收完成。0.7.0 是准备取消边界修复前的中间测试包，以 0.7.1 为准。

- 在专用只读来源中，每个导出项单独准备；来源目录备份按用户确认范围准备。已有 USB 与旧伴侣路径保持原稳定读取流程。
- 列表扫描仍只读取必要索引，不预复制全部正文。开始导出时复制所选资源，笔记附带索引仅用于内部复核，单项正式输出不附整库索引。
- 准备异步进行，枚举前后核对目录、大小、类型和时间，并对所有文件再次读取核对 SHA-256；活动 WAL/journal 阻止就绪。
- ready 后仅按资源 ID 读取伴侣私有副本，不再从实时来源文件拼接续传字节。Mac 核对固定大小、SHA-256、来源版本及持久化清单身份。
- 每份上限 1 GiB，总资源上限 2 GiB，并保留 256 MiB 设备空间；最多 20,000 项、64 层。准备串行，清单分页最多 200 项且限制响应大小。
- 默认闲置租期 24 小时，访问时续租；正常发布或取消后释放，释放失败在后续同来源内容操作重试，过期回收兜底。服务重启保留 ready 副本、清除未完成准备。
- 来源撤销、来源移除及清除 Mac 配对会使设备固定副本失效并清理；每次状态和分块读取仍检查当前权限。
- Mac 暂停及跨启动手动继续使用原快照 ID；过期后清理未发布缓存并提示创建新任务，不默默重新采集或混用旧偏移。发布后回执丢失可通过完整清单与哈希恢复。

固定副本只保证 ready 后资源不再变化。准备期间多次观察未见变化，仍不等同于原应用数据库与附件的同一时刻事务快照；原始页面转换和完整可恢复备份仍未开放。

本轮隔离来源为 Hanvon-Snapshot-Check-9C17F4，包含合成索引、64 MiB 资源、页面文件与空目录。已完成以下真机验证：

- 设备固定副本准备成功，下载暂停时核对到 46 MiB 未发布缓存；退出重开后任务、快照 ID 与清单哈希保留。
- 暂停后，通过 USB 将合成源资源替换为同大小、不同 SHA-256 的文件并读回核对。用户停止并重新开启无线服务后，Mac 原配对自动连接，继续同一快照，界面观察到 54.5 MB / 67.1 MB。
- 最终 64 MiB 输出与变更前种子逐字节及 SHA-256 一致，与变更后的设备源不同；页面资源和空目录保留，单项 raw 不附整库索引。快照释放获得设备确认。随后已通过 USB 恢复原合成源文件。
- 另一个任务在准备阶段暂停后取消，设备快照释放获得确认，未发布目录不存在。
- 原“我的下载”目录独立完成无线上传和下载，44 字节合成文件逐字节及 SHA-256 一致。

来源移除最后以设备列表和实际读取请求共同核对：用户确认来源从伴侣列表消失后，Mac 读取到“尚无内容来源”，旧快照任务重试被拒绝并显示来源已不存在。该任务的 63 MiB 未发布缓存和暂存目录已清理，两份已完成输出的 SHA-256 均保持不变。此前来源仍有授权时发生的续传没有计作撤销成功。

移除后再次在原“我的下载”目录完成无线上传与下载，44 字节样例逐字节及 SHA-256 一致。通过 USB 逐文件读回核对后，清除隔离来源目录及两个普通文件测试样例；本机合成夹具、四项内容测试记录、四项文件测试记录和对应空续传缓存已清理，其他记录及原配对保留。 清理后重开工具箱，原配对自动连接，“我的下载”为空，来源列表和内容测试记录均为空。

联调修复了来源窗口的离线显示：离线明确标注上次读取结果，禁用刷新和扫描操作，避免旧授权被误认为当前状态；新版 Mac 已完成签名构建。

本轮未实测自然等待 24 小时到期或设备空间不足场景；期限与配额实现不能写成这些场景已获真机验收。

## 第二阶段 无线只读来源

伴侣 0.6.0 与对应 Mac 构建增加独立内容来源管理。原可读写共享目录、旧配对令牌和 TLS 身份不变，不给已有 Mac 自动添加内容权限。

- 设备端通过系统选择器添加只读笔记或文件收集目录，最多八个来源。
- Mac 在“内容导出 → 无线来源”申请访问，两端显示相同六位请求编号；实际授权必须在电纸书完成。
- 授权绑定配对令牌摘要、来源 ID 与授权版本。每个目录读取、文件元数据与分块请求都重新验证权限。
- 撤销访问或重新选择来源会更新版本，旧请求不能读新授权；检测到拒绝后清理未发布的 Mac 缓存，已完成输出保留。
- 新来源通过独立路由和只读连接访问，上传、目录修改、删除、移动和 APK 安装不会转发到原文件管理接口。
- 来源绑定不依赖原文件管理目录的位置。删除内容来源时，若 URI 仍被原文件管理使用，会保留原管理目录的权限。
- 本阶段仍采用稳定读取和整文件校验，不提供不可变快照或事务一致性保证。

此阶段自动化为 66 项 Swift 测试、11 个套件，通过；新增九项覆盖只读接口、来源/版本隔离、来源及配对撤销清理、暂停任务的授权刷新、描述验证、访问请求校验及旧记录兼容。Java 权限策略测试覆盖配对身份、授权版本、撤销、严格 ID 和十分钟请求有效期。

已准备位于共享存储顶层、原“我的下载”管理目录之外的合成来源 Hanvon-Source-Check-6A40F2，并补入 64 MiB 合成资源以验证暂停和撤销清理。0.6.0 APK 已通过 USB 发送到 Download 并读回校验，用户已完成覆盖安装和测试来源选择。

Mac 用原配对自动连上 0.6.0，未批准的来源显示为“未授权内容来源”，实际目录名未暴露。用户在设备上核对请求编号并批准后，来源实际名称出现，Mac 成功读取合成笔记索引。界面验收发现行内操作不便键盘访问，已改为列表选中项与底部独立操作按钮。

独立来源首个导出任务包含 64 MiB 文件、页面资源及空目录；暂停时保留 33 MiB 缓存，退出重开后继续完成。最终资源逐字节及 SHA-256 均与种子一致，空目录保留，单项输出没有附带整个索引数据库。Mac 重开后原来源授权仍有效，无需再次批准，原文件管理仍指向“我的下载”。

第二个隔离任务暂停并保留 30 MiB 未发布缓存后，用户在设备撤销该来源的 Mac 访问。刷新来源后实际目录名重新隐藏，任务显示授权已撤销，未发布缓存及暂存目录已清理；已完成副本的 SHA-256 保持不变。再次点击旧任务“继续／重试”，服务端拒绝读取，界面显示来源未授权或已撤销。随后在原“我的下载”目录完成独立的无线上传与下载，44 字节合成文件逐字节及 SHA-256 一致，证明原读写授权仍可使用。

测试结束后，通过 USB 逐文件读回核对并清除了设备隔离目录及原共享目录中的测试文件。本机合成夹具、临时导出、两项内容测试记录、两项文件传输测试记录及对应空缓存已清理，其他历史保留。再次打开 Mac 工具箱，原配对自动重连，原共享目录正常显示。用户随后移除了设备端测试来源登记；Mac 刷新显示“尚无内容来源”，清理闭环完成。

## 第一阶段 已验收功能

- 工具栏“内容导出”入口和独立窗口；原双栏浏览位置不变。
- USB 默认 notes 目录扫描，或将当前可访问目录作为笔记库扫描。
- 通过现有伴侣授权目录进行无线索引读取和目录导出；不扩展原目录权限。
- 本机只读 SQLite 解析，检查普通表、字段、重复键、目录标识、保护状态及执行限制。
- 列出标题、目录修改时间与已观察类型；笔记和便签仍标为未分类。
- 单项原始目录副本、来源目录原始备份、已导出文件收集。
- 筛选、多选、“筛选外已选”提示和导出目标选择。
- 必要隐藏文件、空目录、逐文件 SHA-256，以及第二次源读取校验。
- 索引在扫描与导出时重新核对；变化、非空事务文件、重名、符号链接或计划外输出阻止发布。
- 独立任务记录、暂停、跨启动手动继续、未完成批次重试和取消清理；已发布结果保留。
- 任务执行使用现有操作占用状态，与普通文件操作及心跳互斥。
- 每项输出为普通 .hanvonexport 文件夹，含 item.json 和 raw；任务目录含 result.json。
- 笔记副本标为“目录副本完成”，明确尚未覆盖未识别的跨目录资源，不宣称完整恢复能力。

第一阶段的内容任务通过第二次源读取校验。第三阶段为新伴侣的专用内容来源增加固定副本，旧连接路径仍保留上述稳定读取流程；完整 M2 的其他差异见技术方案实现增量。

## 使用方式

1. USB 连接后，打开“内容导出 → 扫描笔记库 → 扫描设备默认笔记库”，确认只读扫描索引。
2. 或在主窗口定位到某个笔记库目录，再选“扫描当前位置笔记库”。当前目录必须包含受支持的 .database/HvNote.db。
3. 伴侣 0.5.0 仅能扫描原授权目录及其子目录；0.6.0 可通过“无线来源”访问单独添加并在设备上批准的只读目录，无需改原共享目录。
4. 收集 PDF、图片、音频或文本时，在主窗口定位到文件所在目录，打开“内容导出 → 收集当前位置文件”。
5. 选择项目并点“导出所选”。来源目录备份会另行说明包含全部隐藏资源与索引。
6. “导出记录”中查看结果。断线或暂停后，在原连接、原设备与原存储可用时手动继续；不会自动切换连接方式。

扫描笔记索引会把索引短暂复制到本机私有临时目录，读取标题等元数据，正常结束后删除临时副本。单项笔记目录输出不附带整个数据库。源数据只读。

## 第一阶段 自动化与真机验证

完整 Swift 回归为 57 项测试、10 个套件，通过；其中新增内容导出 12 项测试，包含参数化案例。

新增覆盖：

- 已知索引、未知类型、缺列、视图、路径穿越、重复键和未知保护状态。
- 列表扫描不下载正文，未入索引目录保留。
- 隐藏资源及空目录导出、相同大小的源变化检测。
- 中断后重开、保留已完成项、取消清理、损坏记录隔离。
- 符号链接输出、大小写冲突、活动数据库事务及输出文件名长度。

N10 Plus 真机使用唯一隔离目录中的合成 SQLite 索引、两条合成笔记、文本文件及空目录，没有将真实笔记正文作为测试夹具。

- USB 和伴侣 0.5.0 无线均完成两条笔记索引与目录导出。
- 无线完成普通文件收集及包含隐藏索引的来源目录备份。
- 四批任务共六项、九个资源，逐字节及 SHA-256 均与种子文件一致。
- 原始目录中的空目录保留，单项笔记输出未包含整个索引数据库。
- 退出重开后记录保留，原配对自动连接。
- 实际无线短暂中断后显示“已中断”，重连后手动重试成功。
- 窗口验收发现并修复了 NSHostingView 自动缩小造成表格被压缩的问题。

第一阶段没有覆盖专用来源和大文件暂停；第二阶段已补充专用来源及 64 MiB 合成资源的实际暂停偏移、跨启动继续和撤销清理。真实笔记大资源与不可变快照协议仍未验收。
